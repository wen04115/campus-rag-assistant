# 演示验收清单

只使用自己有权处理的测试资料。检查真实问答会产生模型用量，不要连续重复点击。

## 自动检查

- 项目根目录运行 `python tests/run_unit.py`，全部通过。
- frontend 内运行 `npm run lint`、`npm test`、`npm run build`，全部通过。
- 推送后检查 GitHub Actions 的 Backend tests、Frontend checks、MySQL migrations。
- MySQL job 必须在 CI 临时库执行；不要对本地业务库运行 tests/verify_mysql.py。

## 手动业务流程

1. 启动迁移已完成的 8002 后端与 Vite 页面，或者使用已验证的 Docker 同源页面（二选一）。
2. A 登录、建一个测试知识库、重命名，上传测试 TXT / 文字版 PDF；相同文件名再次上传不会覆盖原文件。
3. 建立索引后提问，确认文字逐步显示，最终标记完成，来源片段与原文相符。
4. 新的完整回答自动出现在历史；浏览器刷新恢复账号后，历史仍存在。
5. 翻页/刷新历史；切换另一个知识库不能显示上一个库的历史。旧回答仅是快照。
6. 退出后刷新不能恢复 A；B 登录不能看到 A 的库。知道 A 的库 ID 也不能读取、写入、索引、提问或查看历史。
7. 上传/删除文档后，未重建索引提问应被拒绝。重新建索引后再试。
8. 非空知识库删除返回冲突，不会顺带删除文档；空测试库删除同时删除其历史，其他库不受影响。
9. 使用无关问题核查拒答效果（不能把少量例题通过称为通用准确率）。
10. 所有旧共享 API 应返回 410；不能用旧共享页面访问其他用户数据。

## 故障检查

- 不携带/伪造/过期 JWT：401。跨用户资源与不存在资源：404。
- 模型失败或流中断：显示回答未完成，不显示成功；失败前未完成的回答不写历史。
- 历史提交失败：普通接口返回失败，流式发送 error 而非 done；不要自动重新调用模型。
- 连接在数据库提交后中断：可能已保存，先刷新历史确认，不能保证 exactly-once。
- 拔网/停止服务时，页面区分读取失败和登录过期，不把所有网络异常当成 401。
- 知识库切换、退出或组件卸载时取消旧页面请求，不能把旧历史展示给新账号。

## 数据与部署

- .env、真实密钥、上传文档、模型缓存、数据库备份不进入 Git。
- 备份应包括 MySQL、data/documents、data/vector_store；GitHub 代码不等于这些数据的备份。
- 索引清理仅停服后执行，先预览、备份，不对活动集合操作。
- Docker 构建/首次真实模型下载可能占较多空间，先确认磁盘位置。不要同时启动多个写同一 Chroma 目录的服务。
- 发布公网前另行完成 TLS、限流、权限复核、备份恢复演练和负载/安全测试。当前演示验收不能替代这些步骤。
